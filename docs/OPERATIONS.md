# Operations

Provision the database parent directory before startup (for the default local path, `install -d -m 0700 .data`). Startup and direct repository open never create a missing database parent; this keeps directory custody validation before lock, database, journal, WAL, or SHM creation.

The release-authorized install consumes `requirements-production.txt`, `uv.lock`, the flat `verify_locked_runtime.py` asset, and the wheel from one GitHub Release. Install dependencies with `uv pip install --require-hashes -r requirements-production.txt`, install the wheel with `--no-deps`, then run `python verify_locked_runtime.py uv.lock --write-manifest runtime-lock-manifest.json`. A normal dependency-resolving wheel install is evaluation convenience, not the locked production closure.

Run `thinkroom serve` from the installed package. Before either lock acquisition or database open, the service converts the SQLite path to one canonical absolute spelling and fails closed if the database path or an ancestor is a symlink, the existing target is not a regular file, or that file has multiple hard-link names. After owning the exclusive `<db>.lock`, it atomically reserves the database basename with `O_NOFOLLOW`, retains its device/inode identity, verifies fd-to-path identity, validates journal/WAL/SHM siblings, and repeatedly reattests both database and lock identity through open, schema preparation, recovery, and worker startup. Every existing ancestor must be owned by root or the effective UID and must be non-writable by group/other principals, except a sticky ancestor owned by root or that same UID; the immediate database directory itself must not be group/other-writable. An existing database and any existing sidecar must be effective-UID-owned, single-linked regular files that are not group/other-writable. DrvFS paths commonly project mode `0777`; use the WSL Linux filesystem. Platforms without POSIX custody fail closed. v0.1.0 creates the canonical schema only when the database is empty. Every existing database family is copied through stable `O_NOFOLLOW` file descriptors to an external temporary snapshot for schema attestation; noncanonical or prerelease schemas are rejected without opening or changing the live database, journal, WAL, or SHM bytes. v0.1.0 performs no auto-upgrade. Recovery then runs before readiness, and the service exposes `/health/live` and `/health/ready`. Unexpected retention-supervisor death clears readiness rather than silently disabling cleanup.

Docker is optional operator-owned reference material, not a v0.2 release authority. Thinkroom does not certify the operator's Docker bridge, Docker Desktop integration, WSL interop, container network, or CI runner. Operators who choose it must complete and verify the supplied checklist themselves. Publication MUST remain loopback-only: use `-p 127.0.0.1:8787:8787`, never `-p 8787:8787` or a public bind. Verify the literal-loopback Host contract, sibling-container denial, non-root UID/GID, read-only root, UID-owned mode-0700 `/data`, health, persistence, resource limits, and ownership-checked cleanup. Do not expose the unauthenticated service directly.

Bundled Agent Skills mutation uses POSIX directory descriptors, `O_NOFOLLOW`, an exclusive target-root `flock`, anonymous `O_TMPFILE` staging, fd-bound no-replace publication, and move-then-validate removal. Every successful directory creation is followed by a parent-directory `fsync`; an open or sync failure removes the newly created empty directory and durably syncs that rollback. Before destructive removal it retains a synced anonymous copy of the validated payload; a post-unlink parent-sync failure restores exact bytes with no-replace publication and durably syncs the rollback. Every ancestor must be owned by root or the effective UID; the target root and managed subdirectories must be effective-UID owned and not writable by group or other principals. Writable ancestors are rejected unless sticky and owned by root or the same effective UID. Install or uninstall therefore fails closed on filesystems or platforms without those primitives; on Windows, run the Skills commands inside WSL on the native Linux filesystem, not under `/mnt/<drive>`. The lock serializes Thinkroom mutation processes. Processes running as the same OS principal are trusted: they can ignore advisory locks, mutate that principal's files, and ptrace its processes, so defending against a malicious same-principal writer is not a claimed boundary. Read-only planning and status do not weaken this mutation boundary.

The scripted backend is for offline mechanics and does not prove model quality. Exact `ScriptedBackend` execution is deterministic and in-process; every non-scripted backend selected by the production Service runs in an owned POSIX child-process session. Native non-POSIX provider execution fails closed. On Windows, the release-authorized v0.2 path is native execution inside WSL on its Linux filesystem; Docker Desktop is an operator-owned alternative.

The process lifecycle has one parent owner and these observable states:

```text
STARTED/SESSION_OWNED
  -> RESULT_RECEIVED | CANCEL_REQUESTED
  -> GROUP_DRAINING
  -> PHYSICALLY_EXITED
```

The child remains its session/process-group leader after sending a bounded JSON result until the parent acknowledges custody. The parent retains the `multiprocessing.Process`, result receiver, concurrency lease, and readiness fence until the leader and every same-group descendant have exited. Cancellation first requests cooperative async cleanup, then sends `SIGTERM`, then `SIGKILL` within bounded grace. Normal result, backend error, malformed output, timeout, cancellation, and shutdown all converge through the same group-draining owner. Caller cancellation arriving during mandatory drain is deferred until physical settlement and then re-raised; it is never converted to success. Provider children receive only the typed request and backend configuration, never the repository. A detached physical invocation retains its concurrency lease and makes readiness fail closed until exit. Backends that deliberately create a new session or escape the inherited process group are outside the in-process adapter contract and must run inside a separately owned container/sandbox.

OpenAI-compatible and Prime Agent backends require credentials/executables supplied through environment variables. OpenAI consumes only `THINKROOM_OPENAI_API_KEY`; ambient `OPENAI_API_KEY` is not an alias and is ignored. Prime has one executable setting: `THINKROOM_PRIME_AGENT_EXECUTABLE`; `THINKROOM_PRIME_EXECUTABLE` is not an alias and is rejected as missing configuration. Optional Prime routing uses `THINKROOM_PRIME_AGENT_PROVIDER`, `THINKROOM_PRIME_AGENT_MODEL`, and `THINKROOM_PRIME_AGENT_THINKING`. `prime_agent_failover` additionally requires `THINKROOM_PRIME_AGENT_FALLBACK_PROVIDER`, `THINKROOM_PRIME_AGENT_FALLBACK_MODEL`, and `THINKROOM_PRIME_AGENT_FALLBACK_THINKING`; `THINKROOM_FAILOVER_PRIMARY_TIMEOUT_SECONDS` must be shorter than the whole `THINKROOM_BACKEND_TIMEOUT_SECONDS` so the fallback retains bounded time. Store API keys in a dedicated effective-UID-owned mode-0600 environment file and reference it from the service manager; never place secrets in source, world-readable unit text, logs, or SQLite. The selected provider is validated before repository open: OpenAI requires an HTTP(S) base URL without userinfo and Prime Agent requires an existing executable file with execute permission. SQLite production mode is single-instance only. Startup attests canonical managed-table SQL (including constraints), columns/defaults/primary keys, indexes, and absence of managed triggers/views before readiness. Because v0.1.0 is the first supported release, prerelease candidate schemas are not migrated: a noncanonical schema fails closed without DDL upgrade attempts. The configured per-job persistence ceiling covers the job, attempts, transitions, provider-call audit, artifacts, and idempotency records in one transaction-checked ledger while reserving a bounded 16 KiB terminal-settlement budget for the final transition, typed error, and attempt closure.

The failover wrapper remains outside two independently process-isolated Prime Agent routes. It attempts the fallback only after the primary returns `PROVIDER_ERROR` or `BACKEND_TIMEOUT`; cancellation, deadline exhaustion, malformed or schema-invalid output, invalid requests, context/output limits, and unsupported phases never cross providers. Both routes share the existing logical semaphore lease and therefore never run concurrently for one phase. Each physical invocation receives an ordered provider-call audit row with its own backend, model, timing, and safe output status. The primary availability failure is settled before the fallback row starts. Attempts snapshot the complete chain; a recovered retry rejects policy drift. If startup finds a failover attempt with physical-call evidence but no terminal attempt settlement, it marks any unfinished call `uncertain`, fails the job as `PROVIDER_ATTEMPT_INTERRUPTED`, and refuses automatic replay. Audit rows never store credentials, raw provider errors, prompts, or responses.

Prime Agent configuration is admitted before use: executable, provider, model, and thinking values must be exact strings without NUL bytes and fit conservative character/UTF-8 byte ceilings. The complete encoded argv and RPC prompt are bounded before subprocess creation or prompt delivery; overflow fails as typed `CONTEXT_LIMIT_EXCEEDED` rather than a raw spawn error. The adapter starts Prime Agent in invocation-local RPC mode with only the built-in IPython tool, no context files, no extensions, and no prompt templates. It deliberately keeps session state and Python skills enabled because native `rlm(...)` admission and child `agent_message` delivery require them. The RPC working directory and session store are a temporary invocation-owned directory, not the Thinkroom repository. Prime Agent still runs model-generated Python with the service account's operating-system permissions, so its executable, installed skills, provider account, and host remain trusted provider infrastructure rather than a security sandbox. The container supervisor propagates the loopback application child's exit status after closing its proxy, so restart-on-failure policy cannot mistake startup failure for success.

For every phase, the parent is instructed to call `rlm(...)` exactly once, end its first turn after admission, wait for a real child message, execute the supplied exact IPython recipe to boundedly poll until that named child is completed, reject any unexpected direct child, delete the named child from the parent registry, boundedly confirm the invocation-local direct-child registry is empty, and only then synthesize the phase's schema-only JSON. Thinkroom ignores an early parent answer and rejects terminal JSON unless the same RPC session reports, in order, a matching child relationship and session name, exactly one host-observed cleanup recipe start, and its non-error cleanup marker correlated by the same `toolCallId`. Cleanup before child custody, duplicate/replayed cleanup calls or results, any tool execution or child custody after cleanup, and a printed marker without the matching recipe execution and tool-call identity are rejected. Prime deletion writes a tombstone and removes the child from messaging and observation; it does not erase transcript/artifact bytes already written or RPC bytes already transported. Prompt rejection, invalid JSONL, missing child proof, missing or forged cleanup evidence, failed assistant turns, premature RPC exit, timeout, cancellation, and JSONL/result byte-limit overflow fail as typed backend errors and converge through the existing process-group cleanup. Because Prime Agent has no supported output-token CLI flag, Thinkroom independently bounds the raw JSONL transport bytes, each JSONL event, the event count, retained control/result events, and terminal assistant text. The raw transport hard cap is 64,000,000 bytes and the record ceiling is 20,000. High-volume token/progress telemetry is parsed but not retained or charged against the result-byte budget; it still consumes the raw transport budget. Stderr is drained without retention to prevent backpressure and is not result evidence; it cannot override valid JSONL success. The invocation timeout and transport ceilings bound the provider stream. The model is also instructed to keep the JSON under the smaller configured limit and 7,000 UTF-8 bytes.

## Reproducible release build

Release artifacts must be built through the repository-owned builder, never with a bare `uv build` whose output can depend on ambient environment:

```bash
python3 scripts/build_release.py --out-dir /absolute/external/empty/dist
```

The builder requires the repository-pinned SHA-256 identity of exactly `uv 0.12.3`, opens the selected binary without following symlinks, copies and hashes the stable file descriptor into a process-private executable, and invokes only that authenticated copy. It uses the exactly pinned `hatchling==1.32.0` backend, overwrites ambient `SOURCE_DATE_EPOCH` with the release value `0`, removes every ambient `UV_*` control except the cache location, sets and passes `--no-config`, passes the intended absolute project path explicitly to `uv build`, requires every isolated build dependency to match `build-constraints.txt` SHA-256 hashes, disables Python bytecode writes, rejects output paths inside the source tree, and rejects non-empty output directories. Release verification uses two fresh source copies, separate caches, deliberately different source mtimes and hostile ambient epoch/project/config/build-control values, then requires same-name wheel and sdist bytes to match exactly. Before accepting output it parses wheel and sdist containers, validates package metadata, rejects unsafe archive members, and verifies every wheel `RECORD` hash and size. Artifact hashes belong to the external exact-candidate evidence; embedding them in package-visible source would change the sdist whose hash is being described.

The container readiness command is `python scripts/healthcheck.py`. It always requests literal `http://127.0.0.1:8787/health/ready`, installs an empty proxy handler, rejects redirects, and does not accept an environment override. It uses explicit nonzero exceptions rather than `assert`, so `PYTHONOPTIMIZE`, ambient proxy variables, redirects, a missing listener, a non-ready endpoint, or a non-200 readiness response cannot turn the container healthy.

All required release smoke checks use explicit exceptions, not Python `assert`; they remain active under `PYTHONOPTIMIZE`/`python -O`. SQLite readiness attests the canonical normalized `sqlite_master` SQL for every managed table in addition to columns, indexes, and forbidden triggers/views. DDL-only constraint tampering therefore fails closed before readiness.
